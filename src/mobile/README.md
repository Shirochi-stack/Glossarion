# Glossarion Mobile (Android + iOS)

Flet 1.0.3 app (Flutter Material 3 UI + embedded CPython 3.13) that runs the
Glossarion backend in-process on phones and tablets. Device builds happen in
GitHub Actions (`.github/workflows/build-mobile.yml`); locally you only need
Python to run the app in a desktop window and to run the host tests.

Status: **U0** (spikes and safety net). The app shows the device-spike screen
(`app/glossarion_mobile/ui/spike.py`); the chat-first UI from `docs/UI_SPEC.md`
replaces it from U1 on.

## Layout

```
src/mobile/
  pyproject.toml            # [project] pins + [tool.flet] build config (bundle id com.glossarion.app)
  backend_manifest.toml     # collector policy (entry modules, exclusions, baselines)
  app/                      # Flet app dir ([tool.flet.app] path = "app")
    main.py                 # runtime_bootstrap.bootstrap() first, then ft.run(main)
    glossarion_mobile/
      runtime_bootstrap.py  # env contract, AppPaths, logging/crash hooks, tiktoken seed, webbrowser, markers
      diagnostics/          # selftest.py (device + host self-test), fixtures.py
      services/native.py    # GlossarionNative bridge (+ desktop stub)
      ui/router.py          # route whitelist (pure Python)
      ui/spike.py           # U0 device-spike screen
    assets/icon.png, splash.png        # committed (1024x1024, from src/Halgakos_NoChibi.png)
    assets/tiktoken/, assets/selftest/ # GENERATED by tools/prepare_assets.py (gitignored)
    backend/                           # GENERATED by tools/collect_backend.py (gitignored)
  extensions/flet_glossarion_native/   # in-repo Flet extension (Python + Dart/Kotlin/Swift)
  tools/                    # collect_backend, prepare_assets, version_info, check_mobile_wheels, build
  ci/                       # android_smoke.sh, package_unsigned_ipa.sh, verify_apk.py, verify_ipa.py
  tests_host/               # host pytest (bootstrap, collector, feature map)
  tests/                    # `flet test` on-device UI tests
  docs/                     # UI_SPEC.md, FEATURE_MAP.md, feature_inventory.toml
```

## Local development (Windows/macOS/Linux)

```bash
cd src/mobile
python -m venv .venv                       # gitignored; Python 3.12+ is fine for desktop dev
.venv/Scripts/python -m pip install flet==1.0.3 flet-secure-storage==1.0.3 \
    flet-permission-handler==1.0.3 pytest  # (macOS/Linux: .venv/bin/python)
# once uv.lock exists: uv sync   (Python 3.13, the exact device pins)

python tools/prepare_assets.py             # tiktoken cache + self-test EPUB into app/assets/
flet run                                   # desktop window; backend imported from the repo src/
python app/main.py                         # same, without the flet CLI
```

* The backend is found in this order: `GLOSSARION_BACKEND_DIR` → the repo `src/`
  (when `app/main.py`'s `parents[2]` contains `TransateKRtoEN.py`) → `app/backend/`.
  Set `GLOSSARION_BACKEND_DIR=src/mobile/app/backend` to test the collected bundle.
* Storage: `flet run` uses `.flet/storage/{data,cache,temp}`; `python app/main.py`
  without `FLET_APP_STORAGE_*` falls back to `src/mobile/storage/` (keep it out of git).
* Desktop dev behaves like the device (`GLOSSARION_MOBILE=1`, no processes) except that
  the native extension is replaced by a stub (no foreground service, notifications,
  share intake or background tasks) and `~` on Windows still expands to `%USERPROFILE%`.
* Flet runs sync handlers on the asyncio loop: UI handlers are `async` and never block;
  blocking work goes to a thread. Built apps hard-exit (no `atexit`), so state is
  flushed on lifecycle `INACTIVE/HIDE/PAUSE`.

### Host checks

The security pins require Pillow 12.3.0 and cryptography 50.0.2. The lockfile
resolves on desktop hosts. As of 7 October 2026, the current PyPI/Flet indexes
provide Pillow 12.3.0 for iOS, but not the configured Android targets, and do
not provide cryptography 50.0.2 for Android or iOS. Device builds therefore
fail the existing wheel check until compatible patched wheels are supplied.
Do not downgrade these pins or bypass the wheel check to make a release.

Untrusted Pillow image reads use `safe_image.open_image`, which restricts
parsers before opening headers. EPS, JPEG2000 and McIdas input is rejected;
ordinary PNG/JPEG/WebP/GIF/BMP/TIFF inputs and Pillow's pixel-bomb guard remain
supported. This protection complements the package updates.

```bash
cd src/mobile
python -m pytest -p no:cacheprovider tests_host -q        # bootstrap, router, self-test, offline page build
python tools/collect_backend.py --check                   # import-closure / GUI-taint / process-spawn ratchet
python tools/collect_backend.py --out app/backend --report build/backend_report.md
python tools/check_mobile_wheels.py                       # every native pin has Android+iOS cp313 wheels
python tools/version_info.py --json                       # 9.13.6 -> build number 9130600

# The device self-test on the host (uses temp storage dirs; prints GLOSSARION_SELFTEST PASS/FAIL):
cd app && FLET_APP_STORAGE_DATA=/tmp/gl/data FLET_APP_STORAGE_CACHE=/tmp/gl/cache \
  FLET_APP_STORAGE_TEMP=/tmp/gl/temp python -m glossarion_mobile.diagnostics.selftest --suite smoke
```

`tests_host/test_bootstrap.py` builds the app page against an in-memory fake Flet
client (no window), including an Android simulation with the real
`flet_glossarion_native` Python class.

## Building

Device builds need Flutter, a JDK 17 and the Android SDK (Android) or Xcode (iOS);
CI installs them. `tools/build.py` wraps `flet build` and injects the version:

```bash
python tools/build.py prepare        # collect backend + assets + verify
python tools/build.py apk            # per-ABI APKs (arm64-v8a, x86_64); debug-signed without a keystore
python tools/build.py aab            # Play bundle (needs the release keystore)
python tools/build.py ipa            # macOS: unsigned unless signing args follow `--`
python tools/build.py apk -- -vv     # extra flet build args after --
```

Version: `--build-version` = `APP_VERSION` from `src/app_version.py`, `--build-number`
= `M*1_000_000 + m*10_000 + p*100` (9.13.6 → 9130600). Never edit the version in
`pyproject.toml`.

### CI (`.github/workflows/build-mobile.yml`)

Triggers: manual dispatch (`targets` all/android/ios, `emulator_smoke`,
`ios_simulator_smoke`), tags `v*`, and `workflow_call` from `build-all.yml`.
Jobs: `prepare` → `android` → `android-smoke` (x86_64 emulator: waits for
`GLOSSARION_READY` + `GLOSSARION_BACKEND_READY`, fires the self-test deep link,
requires `GLOSSARION_SELFTEST PASS`) → `ios` (unsigned) → `ios-signed` (only with
secrets) → `ios-simulator-smoke` (optional) → `release` (tags).

Artifacts: `Z_Glossarion-Android-APK`, `Z_Glossarion-Android-AAB`,
`Z_Glossarion-iOS-Unsigned` (AltStore/SideStore), `Z_Glossarion-iOS-Signed`,
`Z_Glossarion-iOS-Simulator`; internal: `mobile-prepared`, `mobile-backend-report`,
`mobile-smoke-logs-*`.

## Signing

All secrets are optional; without them CI ships a debug-signed APK and an unsigned IPA.

| Secret / variable | What it is |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 glossarion-release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ANDROID_KEY_ALIAS` | key alias (e.g. `glossarion`) |
| `ANDROID_KEY_PASSWORD` | key password (defaults to the keystore password) |
| `IOS_DIST_CERT_P12_BASE64` | Apple distribution certificate + key, `.p12`, base64 |
| `IOS_DIST_CERT_PASSWORD` | `.p12` password |
| `IOS_PROVISIONING_PROFILE_BASE64` | provisioning profile for `com.glossarion.app`, base64 |
| `IOS_TEAM_ID` | Apple team id |
| variable `IOS_EXPORT_METHOD` | `release-testing` (default), `app-store-connect`, `debugging`, … |
| variable `IOS_SIGNING_CERTIFICATE` | optional certificate name override |

Create the Android key once and keep it forever (a new key cannot update installed apps):

```bash
keytool -genkeypair -v -keystore glossarion-release.jks -alias glossarion \
  -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 glossarion-release.jks > keystore.b64   # paste into ANDROID_KEYSTORE_BASE64
```

Locally, `flet build` reads `FLET_ANDROID_SIGNING_KEY_STORE`,
`FLET_ANDROID_SIGNING_KEY_STORE_PASSWORD`, `FLET_ANDROID_SIGNING_KEY_PASSWORD` and
`FLET_ANDROID_SIGNING_KEY_ALIAS`.

## Runtime contract (runtime_bootstrap.bootstrap)

Runs before Flet and before any backend import; idempotent (Android may restart
the Dart VM while Python keeps running).

* Paths: `<data>` = `FLET_APP_STORAGE_DATA` (also the cwd), `<cache>` =
  `FLET_APP_STORAGE_CACHE`, `<temp>` = `FLET_APP_STORAGE_TEMP`, `<docs>` = iOS
  `Documents/Glossarion` (Files-visible; from the HOME captured before the override)
  or `<data>` elsewhere.
* Env: `GLOSSARION_MOBILE=1`, `GLOSSARION_NO_PROCESSES=1`,
  `GLOSSARION_HEADLESS_KEY_MANAGER=1`, `GLOSSARION_APP_DIR`/`GLOSSARION_DATA_DIR=<data>`,
  `CONFIG_FILE=<data>/config.json`, `HOME=<data>/home`, `OUTPUT_DIRECTORY=<docs>/Output`,
  `GLOSSARION_LIBRARY_DIR=<docs>/Library`, `GLOSSARION_LOG_DIR=<data>/logs`,
  `GLOSSARION_MODEL_CATALOG_CACHE=<cache>/model_catalog_cache.json`, `XDG_CACHE_HOME=<cache>`,
  `TMPDIR/TEMP/TMP=<temp>`, `TIKTOKEN_CACHE_DIR=<cache>/tiktoken` (seeded from
  `assets/tiktoken`, checked against its `MANIFEST.toml`), `SSL_CERT_FILE` =
  `REQUESTS_CA_BUNDLE` = certifi, `GLOSSARION_HTTP_LOG=0`,
  `GLOSSARION_OAUTH_RETURN_URL=glossarion://app/oauth/return`,
  `USE_ASYNC_CHAPTER_EXTRACTION=0`, `PDF_EXTRACTION_WORKERS=1`, `QA_USE_THREAD_EXECUTOR=1`;
  bookkeeping: `GLOSSARION_PLATFORM`, `GLOSSARION_ORIGINAL_HOME`.
* `threading.stack_size(16 MiB)` for every new thread. Never call
  `threading.stack_size()` without an argument: that resets it to the default
  (use `runtime_bootstrap.current_thread_stack_size()`).
* Logs: `<data>/logs/run.log` (2 MB × 5), `crash.log` (faulthandler; a non-empty tail
  after the last `=== boot` header means the previous run crashed), `selftest-last.json`;
  Flet also writes `<cache>/console.log`.
* `webbrowser.open()` → preferred `glossarion-inapp` controller → UrlLauncher
  `IN_APP_BROWSER_VIEW` (Custom Tabs / SFSafariViewController), so the desktop OAuth
  loopback flows run unchanged.

### Device log markers

Printed to `sys.stderr`, which Flet routes to logcat tag `flet.python` (Android) and
os_log (iOS) plus `console.log`. (`sys.__stderr__` is fd 2 = `/dev/null` on Android.)

| Marker | When |
|---|---|
| `GLOSSARION_BOOT {json}` | end of bootstrap |
| `GLOSSARION_READY` | the first page is built |
| `GLOSSARION_BACKEND_READY modules=<n> secs=<s>` | warm import finished (`n` = backend modules loaded) |
| `GLOSSARION_BACKEND_FAIL {json}` | warm import failed |
| `GLOSSARION_SELFTEST PASS {json}` / `FAIL {json}` | self-test finished (deep link or button) |
| `GLOSSARION_SPIKE …` | U0 spike results (FGS ticks every 60 s, events) |

```bash
adb logcat -s flet.python
adb shell am start -W -a android.intent.action.VIEW \
  -d "glossarion://app/__selftest__?suite=smoke" com.glossarion.app
xcrun simctl openurl booted "glossarion://app/__selftest__?suite=smoke"
```

Routes: only `/`, `/__selftest__` and `/oauth/return` are acted on (U0). Flet hands
Python the path form of a deep link (`glossarion://app/x?y` → `/x?y`); everything
else (content:/file: paths from Open-with, foreign links) is ignored and recorded.
On iOS a cold-start `glossarion://app/...` link is swallowed by receive_sharing_intent's
UIScene hook; the extension re-delivers it as a shared item (`kind="url"`,
`source="launch"`), which the spike routes through the same whitelist (de-duplicated
against `page.route`).

## U0 device spike checklist

Install the debug APK / unsigned IPA and use the spike screen:

1. **Self-test**: "Run self-test" (or the deep link) → PASS.
2. **SecureStorage**: round-trip PASS.
3. **Foreground service**: grant notifications, "Battery: ignore optimizations", Start,
   lock the phone for 20+ minutes; the notification text keeps ticking and `max gap`
   stays < 5 s. Press **Stop** in the notification → card reports
   "notification Stop button".
4. **Notification**: shown on the `jobs.action` channel; tapping it reports the event.
5. **Open-with / Share**: open an EPUB/PDF with Glossarion, and share one to it, both
   cold and warm → items listed, page.route unchanged (PASS).
   iOS: also open `glossarion://app/__selftest__?suite=smoke` while the app is NOT
   running → the self-test still runs (launch-link item routed).
6. **OAuth loopback**: the in-app browser opens the 127.0.0.1 page, which returns to
   the app via `glossarion://app/oauth/return` → PASS (Android: Custom Tab stays open
   behind the app; iOS: SFSafariViewController closes).
7. **16 MiB stacks**: PASS without a crash (`crash.log` stays empty).
8. **iOS**: begin/end background task shows the remaining time; on iOS 26
   "Continued processing" counts to 60 in the system UI, also when backgrounded.

Record the outcome per device (model, OS version) and the fallback chosen for any
failure (notifications → native fallback, Open-with entry point, BG identifiers).
